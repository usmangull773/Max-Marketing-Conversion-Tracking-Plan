Conversion Tracking Plan

Max Marketing Firm: Google Ads, GA4 and GTM tracking review

Prepared for Viktoriia Tarakanova and the Max Marketing Firm team. 16 September 2026. Prepared by Usman Gull.

What we found

This review was run against the live maxmarketingfirm.com front end before any call. Everything below was observed in the browser, not assumed from the job description.

The headline: GA4 is collecting cleanly, but there is no Google Ads conversion signal leaving the site at all. Every other issue on this page sits downstream of that one.

Finding 01

No Google Ads conversion tag is firing on any page

The container GTM-WVGF8LFM loads and resolves two tag IDs: G-RD6HFY39XN and GT-WVCLCVGJ. There is no AW- conversion ID anywhere in the loaded tag set, and the configured destinations list is empty.

Across a full page load of the home page and the contact page, the only measurement request sent is google-analytics.com/g/collect. Nothing is sent to googleadservices.com/pagead/conversion or to googleads.g.doubleclick.net.

What this means: Google Ads is receiving no first party conversion from the website, and with no Conversion Linker in place the gclid is never written to a first party cookie. Any conversion that does get imported later will be missing its click attribution.

Finding 02

The contact form cannot be caught by the built in Form Submission trigger

The form on /contact is a Next.js Server Action. Its hidden fields are $ACTION_REF_1, $ACTION_1:0 and $ACTION_KEY, which means the submission is handled in React and never performs a native browser form submit or a redirect to a thank you page.

The form also carries a Cloudflare Turnstile challenge field, cf-turnstile-response. Turnstile intercepts and defers the submit event, which breaks the timing that GTM's native trigger depends on.

What this means: A standard Form Submission trigger here either never fires or fires before the lead is actually accepted, which is one of the two most common sources of a conversion count that does not match the CRM.

Finding 03

The LeadConnector chat widget is inside a shadow DOM, so click triggers cannot reach it

The site loads the GoHighLevel LeadConnector widget from beta.leadconnectorhq.com/chat-widget/chat-widget.esm.js, config ID 69a36cac95fbc5f3a9d86995. It is a Stencil web component and it renders inside a closed shadow root.

The widget also pulls in intl-tel-input and libphonenumber-js, which confirms a phone number is being captured inside the widget itself.

What this means: GTM Click and Element Visibility triggers do not pierce shadow DOM. Every lead and every phone number that comes through the widget is currently invisible to both GA4 and Google Ads. This is the single highest value fix on the list, because it is where the leads actually are.

Finding 04

The dataLayer has no custom implementation

Across both pages tested, the dataLayer contained only container level entries: gtm.js, gtm.dom and two anonymous consent frames. There is no form_submit, no generate_lead, no page_view push on route change.

The site is a Next.js application with client side routing, so navigating between pages does not create a new page load. Without a manual history based page view push, GA4 sees a single page per session and the path that led to a lead is lost.

Finding 05

Click to call is unconfigured, and Consent Mode is not being signalled

The contact page carries one tel: link with no click tracking attached to it, and there is no call conversion with a minimum duration threshold in place, so a two second misdial would count the same as a booked consultation.

The contact form collects two explicit consent fields, consentNonMarketing and consentPromotional, but no corresponding Consent Mode v2 state is pushed to the dataLayer. The permission is being collected and then not passed to Google.

Finding 06

The duplicate conversion risk sits in the next step, not the current one

The job post mentions duplicate conversions, and this is where they will appear. The moment a native Google Ads conversion action is added while the GA4 key event is also imported into Google Ads, the same form fill is counted twice.

The rule I apply: one action, one source of truth. Native Google Ads tags for anything used for bidding, GA4 key events left for analysis and kept out of the Ads conversions column, and a deduplication ID on any event that can arrive by more than one path.

The 30 day plan

  1. Session one, live on the call

    Install the Google Ads tag and Conversion Linker, then prove they fire

    Add the AW- tag through the existing GTM container, set the Conversion Linker to fire on all pages, and confirm the gclid is landing in the first party cookie. We watch the network panel together so you can see the conversion request leave the browser. This is the step that turns on attribution for everything after it.

  2. Session one, live on the call

    Bridge the Next.js form into the dataLayer

    Push a generate_lead event from the Server Action success state rather than from the submit event, so the conversion fires only after the lead is genuinely accepted and Turnstile has cleared. Then a Custom Event trigger replaces the native Form Submission trigger, which is the part that is failing today.

  3. Session one, live on the call

    Instrument the LeadConnector widget through its own message events

    Because the widget sits in shadow DOM, we listen on the LeadConnector postMessage and widget lifecycle events instead of clicks, and push a named dataLayer event when a chat lead is submitted. I will write the listener with you on screen so your engineer can reuse the same pattern on client sites.

  4. Session one, live on the call

    Set up click to call and Google Ads call reporting with a duration floor

    Click tracking on every tel: link, calls from ads tracked through a Google forwarding number, and calls from the website tracked with number insertion. A minimum call length is set so only real conversations count, which stops short misdials inflating the conversion column.

  5. Session one, closing 30 minutes

    Deduplicate, connect and verify end to end

    Link GA4 to Google Ads, decide per action which single source counts it, apply transaction and event IDs where an event can arrive twice, then verify the whole set in GTM Preview, Tag Assistant and GA4 DebugView while you watch. We do not close the call until Google Ads shows the conversions arriving.

  6. Days 2 to 30, after the session

    Confirm the numbers reconcile, then package it as a repeatable process

    At 72 hours and again at 14 days we compare Google Ads conversions against GA4 and against what actually landed in GoHighLevel, and correct any gap. You get a written container map and a checklist you can run on client accounts without me.
